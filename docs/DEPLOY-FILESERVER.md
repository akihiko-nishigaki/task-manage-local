# 配布手順: ファイルサーバー運用（方式 B）

各自の PC にアプリを入れ、**データだけをファイルサーバーの共有フォルダに置いて**、みんなで同じタスクを使う運用の手順です。
サーバー役の PC は要りません。**10 人以下**で、同時に書き込む場面が少ない使い方を想定しています。

> 常時起動できる PC を 1 台用意できるなら、そちらの方式（`install-server.bat`）のほうが安全です。
> 詳しくは [README](../README.md) の「社内で共有して使う（複数人）」を参照してください。

## 全体の流れ

```
[管理者]  1. 共有フォルダを用意する ─ 2. 配布物を置く ─ 3. 2〜3 人で試す
                                                            │
[参加者]  4. 各自の PC にインストール（共有フォルダを指定）─ 5. 動作確認
```

| 役割 | やること | 目安 |
| --- | --- | --- |
| 管理者（1 人） | 共有フォルダの準備、配布物の用意、試験運用、案内 | 30 分〜 |
| 参加者（全員） | Node.js の確認、インストール、動作確認 | 5 分 |

---

## 管理者がやること

### 1. 共有フォルダを用意する

ファイルサーバーに、データ置き場のフォルダを 1 つ作ります（例: `\\fileserver\share\task`）。

- 参加者全員に「**変更**」の権限（読み取り + 書き込み + 削除）を付けます。読み取りだけでは動きません。
- フォルダは**データ専用**にします。配布物（zip）とは別のフォルダにしてください。
- このフォルダには、アプリが次のファイルを自動で作ります。人が直接触る必要はありません。

  | 名前 | 内容 |
  | --- | --- |
  | `tasks.db` | すべてのタスクのデータ |
  | `backups\` | 自動バックアップ（12 時間ごと・最大 30 世代） |

- ファイルサーバー側のバックアップ（スナップショットなど）の対象にも含めてください。

### 2. 配布物を用意する

1. GitHub の[リリース](https://github.com/akihiko-nishigaki/task-manage-local/releases)から、**v0.4.0 以降**の `TaskManage-Setup-vX.Y.Z.zip` をダウンロードします。
   - 共有フォルダ運用に対応しているのは v0.3.0 以降です。それより前の版では使えません。
   - 共有と個人のデータを画面で切り替えられるのは v0.4.0 以降です（使わないなら v0.3.x でも構いません）。
2. zip を、参加者が見られる別の共有フォルダ（例: `\\fileserver\share\task-setup`）に置きます。**展開はしません。**

### 3.（任意）参加者向けの「ワンクリック版」を作る

PowerShell のコマンドを打てない人がいる場合は、次の内容のファイルを作って zip と一緒に置くと、ダブルクリックだけで済みます。
ファイル名は `install-shared.bat`、**共有フォルダのパスを自分の環境に書き換えて**ください。

```bat
@echo off
rem Run this next to install.bat (after extracting the zip).
call "%~dp0install.bat" -SharedDataDir "\\fileserver\share\task"
```

- パスは**半角英数字だけ**にしてください（日本語が入ると文字化けすることがあります）。
- 日本語を含むパスしか使えない場合は、`install.bat` ではなく、PowerShell で直接実行する方法（後述）にしてください。
- このファイルは、zip を「すべて展開」したフォルダの中（`install.bat` と同じ場所）に置いてもらいます。

### 4. 試験運用（2〜3 人）

全員に配る前に、実際のファイルサーバーで 2〜3 人で試してください。**この確認が一番大事です。**
動作確認は、ネットワーク共有（`\\localhost\c$`）で擬似的に行っただけで、本物のファイルサーバーではまだ確認できていません。

| 確認項目 | 期待する結果 |
| --- | --- |
| 1 人目が起動する | 設定画面に「共有フォルダ運用中」と出る。共有フォルダに `tasks.db` ができる |
| 2 人目が起動する | 1 人目が作ったタスクが見える |
| 1 人目がタスクを追加する | 2 人目の画面に、20 秒以内（またはタブに戻ったとき）に反映される |
| 2 人が同時にタスクを追加・移動する | エラーが出ず、両方の変更が残る |
| 共有フォルダに `backups\` ができる | 起動後に `tasks-日付-時刻.db` が 1 つ以上ある |
| ネットワークを切って起動する | 「共有フォルダに接続できません」とメッセージが出る |

問題がなければ、全員への案内に進みます。

### 5. 参加者へ案内する

次の内容を、メールやチャットで伝えます（そのまま使えます）。

> **タスク管理ツールのインストールのお願い**
> 1. Node.js 22.13 以上が入っているか確認してください（無ければ https://nodejs.org/ja の LTS 版）。
> 2. 配布フォルダ `\\fileserver\share\task-setup` の zip を**自分の PC にコピー**して、右クリック →「すべて展開」します。
> 3. 展開したフォルダの `install-shared.bat` をダブルクリックします。
> 4. 画面の最後に「インストールが完了しました」と出れば完了です。デスクトップの「タスク管理」で起動します。
> 5. 設定画面に「共有フォルダ運用中」と出ていることを確認してください。
>
> ※ みんなで同じデータを使います。共有フォルダの `tasks.db` を、エクスプローラーで直接コピー・編集・削除しないでください。

## 参加者がやること

1. **Node.js 22.13 以上**が入っているか確認します。
   コマンドプロンプトで `node -v` を実行して、`v22.13` 以上と出れば OK です。無ければ https://nodejs.org/ja の LTS 版を入れます。
2. 配布された zip を**自分の PC にコピー**して、右クリック →「すべて展開」します。
   （共有フォルダの中で直接展開・実行すると、動作が遅くなったり失敗したりします）
3. 展開したフォルダで、次のどちらかを実行します。

   **A. ワンクリック版がある場合:** `install-shared.bat` をダブルクリックします。

   **B. ない場合:** 展開したフォルダで PowerShell を開き、次を実行します（共有フォルダのパスは管理者に聞いてください）。

   ```
   powershell -ExecutionPolicy Bypass -File install.ps1 -SharedDataDir \\fileserver\share\task
   ```

4. インストーラーが次を行います。
   - 共有フォルダへ読み書きできるかを確認します。できなければ、理由を表示して中断します（インストールは行われません）。
   - アプリを `%LOCALAPPDATA%\Programs\TaskManage` に入れ、デスクトップに「タスク管理」のショートカットを作ります。
5. デスクトップの「**タスク管理**」を開き、「設定」画面で **「共有フォルダ運用中」** と出ていることを確認します。

> **すでに自分の PC でこのツールを使っていた人へ:** 以前のデータは共有フォルダへ**自動では移りません**。
> 引き継ぐときは、先に旧画面の「設定」→「エクスポート」で JSON を保存し、共有版の「設定」→「インポート」（「マージ」）で取り込みます。
> 複数の人が同じ内容をインポートすると重複するので、**代表の 1 人だけ**が行ってください。

## 個人用のデータも使いたい場合（v0.4.0 以降）

共有のタスクとは別に、**自分だけのタスク**（メモ・下書き・個人の ToDo など）を持ちたい人は、同じアプリの中に「個人」のデータを追加して、画面で切り替えて使えます。
個人用のデータは**自分の PC の中にだけ**保存され、共有フォルダには置かれないので、ほかの人には見えません。

### 追加のしかた（個人用を使いたい人が、それぞれ自分の PC で）

1. アプリを開き、「設定」→「**データの切り替え**」を開きます。
2. 「データを追加」の名前に「個人」などと入れ、**保存場所は空のまま**「追加」を押します。
3. 一覧に「個人（この PC）」が出るので、「**切り替え**」を押します。
4. 左上に「**使っているデータ**」の選択が出ます。以後は、ここで「共有（共有フォルダ）」と「個人」をいつでも切り替えられます。

### 知っておくこと

| 項目 | 内容 |
| --- | --- |
| 中身は完全に別 | 共有と個人では、タスク・メンバー・タグ・プロジェクトが混ざりません。「現在のユーザー」もデータごとに選びます |
| 個人用の追加は各自の PC だけ | 追加した一覧は、その PC にだけ保存されます。管理者が全員の分を設定する必要はありません |
| **個人用のバックアップ** | 個人用のデータは、共有フォルダの**自動バックアップの対象外**です。「設定」→「エクスポート」で、ときどき JSON を保存してください（復元は「インポート」） |
| 最初のデータは共有 | 共有フォルダを指定してインストールした場合、「最初のデータ」が共有になります。一覧から外せません |
| 一覧から外す | 個人用を「一覧から外す」と画面から消えますが、**データのファイルは消えません**。同じ場所を指定して追加し直せば、また使えます |
| どちらを開いているか | 個人用のタスクを共有に入れてしまわないよう、**追加する前に左上の表示を確認**してください |

### 管理者へ

- 共有フォルダ運用に対応しているのは v0.3.0 以降、**個人用データの切り替えは v0.4.0 以降**です。配布する zip は v0.4.0 以降にすると、全員が個人用も使えます。
- 個人用データの追加は、参加者の自由です。使わない人は何もしなくて構いません（左上の切り替えも出ません）。
- 個人用のデータは、共有フォルダにも、ファイルサーバーのバックアップにも入りません。

## 更新するとき

**全員が同じ版**のアプリを使う必要があります。

1. 管理者が、新しい版の zip を配布フォルダに置きます（古い zip は消すか、名前を変えて残します）。
2. 全員に「いつ更新するか」を伝え、**更新の時間帯は使わない**ようにしてもらいます。
3. 各自が、新しい zip を自分の PC に展開して `install.bat`（または `install-shared.bat`）を実行します。
   共有フォルダの指定は前回の内容が**引き継がれる**ので、`install.bat` だけで構いません。
4. 更新後にデータの形式が変わる版では、**最初に新しい版を起動した人**がデータを更新します。
   このとき、まだ古い版のままの人は、データを開こうとすると次のメッセージが出て起動しません（データは壊れません）。

   > このデータは新しいバージョンのアプリで更新されています。アプリを最新版に更新してから起動してください。

   その場合は、その人が更新を行えば使えるようになります。

## うまくいかないとき

| 症状 | 原因と対処 |
| --- | --- |
| インストールで「共有フォルダに接続できません」 | パスが違う、ネットワーク（VPN など）に繋がっていない。パスをエクスプローラーで開けるか確認する |
| インストールで「共有フォルダに書き込めません」 | 権限が「読み取り」だけ。管理者に「変更」権限を付けてもらう |
| 起動したがメッセージが出て開かない | メッセージの内容に従う（接続できない・データが新しい版・整合性エラーのいずれか） |
| 設定画面に「共有フォルダ運用中」と出ない | 共有フォルダの指定が効いていない。`install.ps1 -SharedDataDir ...` を付けて入れ直す |
| 左上に「使っているデータ」が出ない | データが 1 つだけのときは出ない。「設定」→「データの切り替え」で個人用などを追加すると出る |
| 追加した個人用が、別の PC に出ない | 追加した一覧は、その PC にだけ保存される。別の PC で使うなら、その PC でも追加する（データ自体は PC ごとに別） |
| 他の人の変更がなかなか見えない | 画面は 20 秒ごと、またはタブに戻ったときに更新される。ページを再読み込みする |
| 保存時に少し待たされる | 同時に書き込む人がいると、最大 15 秒ほど待つことがある。通常はすぐ終わる |
| 起動時に「整合性の検査に失敗した」と出る | データが壊れている。下の「データが壊れたとき」で戻す |

### データが壊れたとき

1. **全員**のアプリを止めます（`%LOCALAPPDATA%\Programs\TaskManage\stop.bat`）。
2. 共有フォルダの壊れた `tasks.db` を、別名（例: `tasks.broken.db`）に変えます。`tasks.db-journal` があれば、それも別名にします。
3. `backups` フォルダの最新の `tasks-日付-時刻.db` を、`tasks.db` という名前でコピーします。
4. 全員でアプリを起動し直します。

バックアップは最大 12 時間おきなので、**最大半日分の変更が失われる**ことがあります。
ファイルサーバー側のバックアップがあれば、そちらのほうが新しい場合があります。

---

## 運用のルール（参加者全員に伝えてください）

- 共有フォルダの `tasks.db` と `backups` を、**エクスプローラーなどで直接触らない**（使用中だと壊れることがあります）。
- 全員が**同じ版**のアプリを使う。
- 個人用のデータは自動バックアップされない。**各自が「エクスポート」で JSON を保存する**。
- 共有と個人を切り替えたときは、左上の「使っているデータ」を確かめてからタスクを追加する。
- ファイルサーバーが止まる、ネットワークが切れると使えなくなる。
- 人数が増える、頻繁に書き込みがぶつかる、止められない業務で使う、という場合は、サーバー役の PC 方式（`install-server.bat`）へ切り替える。

## 元に戻す・やめるとき

- **自分だけ共有をやめて、自分の PC だけで使う:** `install.ps1 -UseLocalData` を実行します（共有フォルダのデータはそのまま残ります。以後は自分の PC 内のデータ（以前ローカルで使っていればその内容、無ければ空）を使います）。
- **アンインストール:** 「設定 > アプリ」から「タスク管理」を削除します。**共有フォルダのデータは消えません**（`-RemoveData` を付けても、消すのは自分の PC のデータだけです）。
